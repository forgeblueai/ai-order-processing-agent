# Work log

Store dated records of meaningful investigation, implementation, and validation in this directory.

Use the filename pattern `YYYY-MM-DD-short-topic.md`. Each entry should include:

- date, repository, branch, and exact baseline SHA;
- objective and bounded scope;
- sources or commands inspected;
- observed results and evidence links;
- explicit limitations and checks not run;
- decisions or open questions changed;
- one concrete next action and acceptance criterion.

Do not store secrets, plaintext credentials, real customer messages, or identifying order data. Do not claim a test was run merely because it exists in documentation. When referencing CI, record the exact SHA and run URL and distinguish that from local validation.
